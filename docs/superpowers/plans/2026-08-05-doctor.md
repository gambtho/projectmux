# Doctor Implementation Plan

> **Status note:** this slice was implemented and fully verified during
> the plan's materialize-verify pass (all gates green, a real-tmux
> orphan lifecycle test, and an isolated end-to-end smoke asserting the
> five-check envelope, exit 0 with findings, and exit 2 on an argument),
> then committed directly rather than re-transcribed task-by-task. The
> committed code is authoritative where it and the summaries below
> diverge. Spec: `docs/superpowers/specs/2026-08-05-doctor-design.md`.

**Goal:** `projectmux doctor` — a strictly read-only diagnosis of the
installation across five checks (dependencies, configuration, database,
orphaned sessions, stale container bindings) that reports findings
without repairing them and exits 0 whenever it produced a report.

**Architecture:** A new `internal/doctor` package owns the diagnosis.
`doctor.Runner` holds one narrow seam per fact source — a version prober,
a bulk session lister, a read-only store view, the container observer —
and `Diagnose` returns a `Report` of fixed-order `Check`s, each
aggregating its `Item`s worst-first. The CLI supplies the seams and
renders the report as human text or a versioned JSON envelope. Doctor
deliberately bypasses `openStore`: a new `state.OpenReadOnly` inspects
the database with `mode=ro`, so a command that reports "migrations are
pending" cannot perform them in the same breath.

**Tech Stack:** Go stdlib plus the existing modernc.org/sqlite driver.
Verified tool behaviors recorded in spec §2 are binding: `?mode=ro` never
creates or writes the file; `PRAGMA integrity_check` returns `ok` on a
healthy database, `database disk image is malformed (11)` on a corrupt
one, `file is not a database (26)` on garbage, and `unable to open
database file (14)` when absent; `docker version --format
'{{.Server.Version}}'` exits 1 with empty stdout when the daemon is down.

## Global Constraints

- No new module dependencies; stdlib plus the existing driver. Linux/WSL
  only.
- `gofmt -l .` empty, `go vet ./...`, `go test ./... -count=1`,
  `go build ./...` before every commit.
- Exit codes 0–6 unchanged. Doctor exits 0 on any successful report and 2
  on a usage error; only an undeterminable config or state root fails it.
- JSON envelope changes are additive to schema version 1.
- Diagnose-only. Doctor never starts, kills, migrates, repairs, or
  rebuilds anything — state rebuild is a later slice.
- Uncertainty never converts to absence. A tool is "not installed" only
  when PATH resolution confirms it; a worktree is gone only on
  `fs.ErrNotExist`; a container is gone only when the probe reports
  `HealthMissing`. Everything else is `unknown`.
- Commit messages and code comments must not mention Claude or AI
  assistance.

### Task 1: Read-only database inspection

**Files:** Create `internal/state/readonly.go`,
`internal/state/readonly_test.go`; modify `internal/state/state.go`
(`DBPath`, `uriPath`) and `internal/state/store.go` (query helpers lifted
onto `*sql.DB` so both stores share them).

**Interfaces (produced):**

```go
func DBPath(root string) string

type PendingMigrationError struct{ Database, Supported int }

type Inspection struct {
	UserVersion  int
	IntegrityErr error
}

func (i Inspection) Usable() error

type ReadOnlyStore struct{ /* ... */ }

func OpenReadOnly(root string) (*ReadOnlyStore, Inspection, error)
func IsMissingDatabase(err error) bool
```

`OpenReadOnly` opens `<root>/state.db` with `?mode=ro`, which never
creates the file: a missing database returns an error wrapping
`fs.ErrNotExist`, not a freshly created empty one. The integrity check is
a finding, not a failure — the store and the inspection both come back,
and `Usable()` reports why the rows must not be read: corrupt, a schema
version newer than this build (`FutureSchemaError`), or older
(`PendingMigrationError`, whose message states that migrations run on the
next mutating command). `ReadOnlyStore` exposes only `Workspaces`,
`Workspace`, and `Close`; every mutation stays on `*Store`.

Eight tests, including the load-bearing one: a byte-identical file before
and after an inspection, and no database created when none existed.
Commit: folded into the slice commit.

### Task 2: Standalone defaults validation

**Files:** Modify `internal/config/validate.go`; create
`internal/config/validate_test.go`.

**Interfaces (produced):**

```go
func ValidateDefaults(l Layer) []string
```

Validation otherwise lives only in `Load`, which needs a slug, so a
`defaults.yaml` would go unchecked on an installation with no workspace
files at all. Defaults are legitimately incomplete — a workspace layer
supplies the rest — so `ValidateDefaults` injects `SchemaVersion` when
`Version` is nil and then runs the ordinary `validate`. Anything defaults
does state is checked as stated. The caller renders the result as a
**warning**, not a rejection, because a later layer may override it.

Tests: an empty, a version-only, and the full defaults document all
report nothing; version 9, a non-portable window name, a modeless window,
and a non-positive `start_timeout` each report their problem, and none of
them reports "version is required".

### Task 3: The doctor package

**Files:** Create `internal/doctor/doctor.go`,
`internal/doctor/dependencies.go`, `internal/doctor/configuration.go`,
`internal/doctor/database.go`, `internal/doctor/sessions.go`,
`internal/doctor/bindings.go`, `internal/doctor/doctor_test.go`.

**Interfaces (produced):**

```go
type Status string

const (
	StatusOK      Status = "ok"
	StatusWarn    Status = "warn"
	StatusUnknown Status = "unknown"
	StatusFail    Status = "fail"
)

type Item struct{ Subject string; Status Status; Detail string }
type Check struct{ Name string; Status Status; Detail string; Items []Item }
type Report struct{ Checks []Check }

type ProbeResult struct {
	Stdout, Stderr string
	ExitCode       int
	Found          bool
}

type VersionRunner interface {
	Probe(ctx context.Context, argv ...string) (ProbeResult, error)
}

type SessionLister interface {
	Sessions(ctx context.Context) ([]controller.LiveSession, error)
}

type Store interface {
	Workspaces() ([]state.Record, error)
	Workspace(id string) (state.Record, error)
}

type Database struct {
	Path                 string
	Missing              bool
	OpenErr, IntegrityErr error
	Version, Supported   int
}

type Runner struct {
	ConfigRoot  string
	Defaults    config.Layer
	DefaultsErr error
	DB          Database
	Store       Store
	Sessions    SessionLister
	Containers  controller.ContainerObserver
	Versions    VersionRunner
}

func (r *Runner) Diagnose(ctx context.Context) Report
```

Aggregation ranks `fail`(3) > `unknown`(2) > `warn`(1) > `ok`(0):
unknown outranks warn because unexamined ground is more alarming than a
known, bounded finding. `verdict(name, status, detail)` builds an itemless
check — one that could not run, or one whose answer is a single sentence.

The five checks:

- **dependencies** — a probe table: `tmux -V` (absent ⇒ `fail`; nothing
  works without it), `git --version`, `docker --version`, `devcontainer
  --version` (absent ⇒ `warn`). A probe error, a nonzero exit, or empty
  stdout is `unknown`; only PATH resolution establishes absence. The
  daemon is probed only when the client was found, and is `ok` only on
  exit 0 with non-empty stdout. `dependencies` returns the check plus a
  docker-absent flag.
- **configuration** — `DefaultsErr` fails the whole check with no items.
  Otherwise the first item is `defaults`: an absent `defaults.yaml` is
  `ok`, a stat error is `unknown`, and `ValidateDefaults` problems are a
  `warn` reading "read alone, defaults.yaml has problems a workspace
  layer would have to override: …". Then each `<root>/workspaces/*.yaml`
  (skipping `*.local`) runs through `config.Load` — `ok` or `fail`.
- **database** — itemless, straight from `Database`: missing ⇒ `ok` ("no
  state database yet"), open error ⇒ `unknown`, integrity error ⇒ `fail`,
  a newer schema ⇒ `fail`, an older one ⇒ `warn` ("migrations run on the
  next mutating command"), otherwise `ok` with the version and path.
- **orphaned-sessions** — sessions without identity keys belong to
  someone else and are skipped. An unregistered workspace ID or a
  worktree confirmed absent is `warn`; any other stat error is `unknown`.
  `Runner.records()` distinguishes confirmed-empty from unknown: a
  missing database returns `(nil, nil)` — a fresh installation, where a
  live identity session genuinely is unregistered — while an existing but
  unusable database returns an error, so no session can be called an
  orphan.
- **stale-bindings** — short-circuits to `unknown` when docker is absent
  (every probe would fail for the same uninformative reason). Otherwise
  one `ProbeContainer` per stored binding: `HealthPresent` ⇒ `ok`,
  `HealthMissing` ⇒ `warn`, anything else or a probe error ⇒ `unknown`.

Twenty-one package tests cover the status matrix for every check plus the
aggregation rule and the always-five-checks invariant.

### Task 4: CLI wiring and the `doctor` command

**Files:** Create `internal/cli/doctor.go`,
`internal/cli/doctor_test.go`; modify `internal/cli/wiring.go` (seams)
and `internal/cli/cli.go` (usage entry, dispatch case).

**Interfaces (produced):**

```go
type doctorEnvelope struct {
	SchemaVersion int           `json:"schema_version"`
	Checks        []doctorCheck `json:"checks"`
}

type doctorCheck struct {
	Name   string       `json:"name"`
	Status string       `json:"status"`
	Detail string       `json:"detail,omitempty"`
	Items  []doctorItem `json:"items"`
}

type doctorItem struct {
	Subject string `json:"subject"`
	Status  string `json:"status"`
	Detail  string `json:"detail,omitempty"`
}

var inspectDatabase = func(root string) (doctor.Database, doctor.Store, func())
var newVersionRunner = func() doctor.VersionRunner
type sessionListerFunc func(ctx context.Context) ([]controller.LiveSession, error)
```

`inspectDatabase` never returns an error: every outcome — missing,
unreadable, corrupt, drifted — becomes report content, and the store is
non-nil only when `Inspection.Usable()` is nil. The returned close is
always safe to call. `toolProbe` separates PATH resolution from execution
so an absent binary is confirmed absence rather than an execution
failure, and runs the probe under `tmux.DefaultTimeout`.

`buildDoctor` fails only on an undeterminable config or state root; a
defaults layer that will not load is passed in as `DefaultsErr` and the
other four checks still run. `doctorEnvelopeFrom` always emits non-nil
`checks` and `items` arrays so consumers never branch on null. Human
output is a tabwriter table, one line per check with indented items; a
`cells` helper drops an empty trailing detail so no line ends in
whitespace.

Seven CLI tests: the five fixed-order checks and non-null arrays, exit 0
with a `fail` finding present, human output, `--compact` implying JSON,
exit 2 on an unexpected argument with nothing on stdout, `--help`, and
the no-mutation guarantee — the real `inspectDatabase` against a temp
state root, asserting no database is created on a fresh installation and
that an existing database is byte-identical afterwards, with `openStore`
replaced by a seam that fails the test if doctor ever takes the mutating
path.

### Task 5: Real-tmux orphan test and final sweep

**Files:** Create `internal/doctor/integration_test.go`.

Real tmux on an isolated socket (`-L projectmux-doctor-…`, killed on
cleanup), a fake store, no container tooling:

- `TestIntegrationOrphanedSessionsAgainstRealTmux` — four sessions: a
  registered workspace with a live worktree (`ok`), a registered
  workspace whose worktree was deleted after registration
  (`warn: worktree no longer exists`), a session claiming an unregistered
  workspace ID (`warn: session not registered`), and a keyless bystander
  that produces no item at all. The identity round-trip through real tmux
  is part of the assertion.
- `TestIntegrationOrphanedSessionsCleanInstallation` — a registered,
  present worktree aggregates to `ok`.

Final sweep, run on the finished branch:

```bash
gofmt -l internal/     # empty
go build ./...
go vet ./...
go test ./... -count=1
```

Isolated end-to-end smoke (temp config and state roots, throwaway
`defaults.yaml`): `doctor --json` on a fresh installation → five checks,
`database: ok "no state database yet"`, exit 0, and an empty state root
afterwards; `doctor` human output; a broken `workspaces/broken.yaml` →
`configuration: fail` naming the window, still exit 0; `doctor
slabledger` → exit 2 with usage on stderr and nothing on stdout. All
asserted; all green.

## Self-review notes

- Spec §1 command surface → Task 4; §2 architecture and verified
  behaviors → Tasks 1, 3, 4; §3 the five checks → Task 3; §4 CLI and
  envelope → Task 4; §5 testing rows → Tasks 1–5.
- Deviation from spec §2: the spec sketched `Runner{… StateRoot string;
  Store …}`. The implementation instead carries a `DB doctor.Database`
  (which holds the path) plus `DefaultsErr`, so the runner never touches
  the filesystem to learn about the database, and `dependencies` returns
  a docker-absent flag rather than having `staleBindings` re-derive
  absence from the dependency items. Inferring absence from an item's
  status was implicit and fragile; the probe now reports it directly.
- Discovery during Task 4: a read-only SQLite connection to a WAL
  database still materializes the `-shm` and `-wal` sidecars, because
  readers need the shared-memory index. The database's own bytes are
  never written, so the no-mutation test asserts content identity and
  permits only those two sidecar names. `inspectDatabase`'s comment
  records the caveat.
- Both locked decisions hold in the code: diagnose-only (no repair path
  exists anywhere in `internal/doctor`) and exit 0 on any successful
  report (`runDoctor` returns an error only for a usage mistake or an
  undeterminable root).
